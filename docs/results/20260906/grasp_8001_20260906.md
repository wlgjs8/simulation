# 8001 왼팔 회색 볼트 파지 실패 분석

대상: `outputs/shared_stack/shared_ft_pi05_8001_box20_final`의 8001 / `boltv2_plain_40k/39999` 실행. 시각은 **정책 시작 기준**이며 원본 overview 영상에는 앞에 약 0.6초의 tare 구간이 있다.

## 결론

왼팔이 회색 볼트 몸통을 두 손가락 사이에 넣는 접근은 이루어졌다. 그러나 볼트를 조여 들어올리는 단계로 전환하지 않고, 열린 그리퍼 목표를 유지하면서 하강을 계속했다. 손끝이 테이블에 닿자 한쪽 손가락이 외력으로 명령보다 안쪽으로 밀렸고 볼트도 옆으로 움직였다. 이후 볼트는 테이블 위에서 끌려갔으며 유의미하게 들리지 않았다.

이 장면의 실패는 22.496초의 추종 오류보다 먼저 발생했다. 접촉 직전에는 C++ 실제 선행 오차가 약 1mm로 작았고, 볼트 위치도 집게 폭 방향으로 크게 빗나가지 않았다. 추종 오류는 이후 하강·테이블 접촉·박스 접촉이 계속되면서 발생한 후속 현상이다.

## 재현 및 검증

- 원본 `chunk_packets.jsonl`과 `policy_steps.jsonl`을 기존 `RecordedPolicySource`로 재생했다. 모델을 다시 추론해서 다른 궤적을 비교한 것이 아니다.
- 원본 설정, seed 100, aligned 장면, 회색/검은색 각 10개, 20mm 박스 벽을 그대로 사용했다.
- 동일한 policy runner, C++ delta_preview, FT, IK 및 안전 필터, PhysX 경로를 실행했다.
- 진단 스크립트는 센서 읽기와 접촉 콜백, 기존 카메라 읽기에 기록만 추가했다. 제어 입력이나 장면 물성은 바꾸지 않았다.
- **11,548개 물리 스텝 / 양팔 23,096개 행의 실제 관절 위치, 목표 위치, 속도 차이가 모두 0이었다.** 설정과 최종 fault 문자열도 일치했다.
- 추가로 100Hz 볼트/TCP/손가락 자세, 500Hz 접촉점·임펄스, 왼쪽 손목 영상을 기록했다. 실제 볼트 움직임에 대한 수치는 이 검증된 재생의 측정치다.

| 9.442초 | FT 보정 변위가 40mm 한계에 도달한다. | 보정이 개입해도 계속되는 하강 요구를 해소하지 못한다. |
| 10.0초 | 정책 명목 Z는 -361.2mm, 실제 TCP Z는 -295.2mm, 테이블은 -295mm. | 정책 기준은 테이블 아래로 계속 진행하지만 실제 팔은 접촉에 막힌다. |
| 13.944초 이후 | 그리퍼 베이스와 회색 박스 벽의 유의미한 접촉력이 발생한다. | 최초 파지 실패 이후의 추가 장애물이다. |
| 22.496초 | 37.55mm 실제 선행 오차로 fault. | 초기 파지 실패의 시작점이 아니다. |

그리퍼의 0%는 닫힘, 100%는 열림이다. 8.5–12초 정책 명령은 **23.66–28.76%**, 현재 Sim의 선형 변환으로 약 **23.2–28.2mm** 개방 폭이다. 볼트 몸통 지름은 12mm, 머리 지름은 18.4mm다. 이 시점의 몸통은 집게 폭 방향으로 거의 중심에 있고, 머리는 손가락 너비 범위 밖에 있다. 따라서 이 넓은 목표를 유지한 채로는 몸통에 정상적인 양쪽 압착력을 만들기 어렵다.

실제 폭은 뒤에 약 10–14mm까지 줄어든다. 이것을 모델이 파지를 지시했다고 해석하면 안 된다. 명령은 여전히 약 25mm 개방을 요구하고 있고, 테이블이 손가락을 밀어 목표에서 벗어나게 한다. 8.65–8.85초의 양쪽 손끝/테이블 합력은 최대 약 305.6N이었다. 이 힘 수치는 현재 잠정 Sim 접촉 물성에서 측정된 것이며 Real의 힘으로 해석하지 않는다.

볼트 02의 전체 실행 중 최대 상승은 **0.201mm**, 마지막 평면 변위는 **159.6mm**였다. 볼트 03도 최대 상승 0.044mm에 불과했다. 안정적으로 집어 들어올린 구간은 관측되지 않았다.

정책 로그의 `cmd_pose`는 FT/안전 보정 전의 명목 기준이다. 위의 -361.2mm를 PhysX에 그대로 보낸 관절 목표라고 해석하면 안 된다. 같은 시각 C++의 실제 선행 오차는 약 3.2mm이며, 정책 기준과 실행된 기준이 크게 벌어진 상태다.

## 확정할 수 있는 범위와 남은 질문

직접 확인된 실패 경로는 **충분한 닫힘·들어올림 전환 부재 → 테이블을 계속 누름 → 손가락이 외력으로 밀림 → 볼트가 옆으로 이동**이다. 따라서 마찰이 부족해 이미 들어올린 볼트가 떨어졌다는 설명은 이 기록과 맞지 않는다. IK 추종이 처음부터 나빠 목표 볼트를 빗나갔다는 설명도 접촉 직전 측정과 맞지 않는다.

모델이 왜 이 관측에서 하강과 약 25% 개방을 계속 출력했는지는 이 한 실행만으로 확정할 수 없다. 영상/카메라/작업면 높이의 Real–Sim 차이, 접촉 후에도 명령 기준 proprio를 사용하는 영향, 실제 모터 percent와 물리적 개방 폭의 보정 차이가 추가 검증 대상이다. Real 경로는 percent를 모터 각도로 변환하지만 Sim은 98mm 전체 개방 폭에 선형 대응시킨다. 전체 개방 폭 측정만으로 중간 percent 구간의 실제 대응 곡선까지 검증되지는 않는다.

다음 개선의 우선순위는 실제 그리퍼 percent–개방 폭 대응을 확인하고, 접촉 직전 같은 상태에서 닫힘/상승 명령을 통제한 Sim 실험으로 파지 가능 여부를 분리하는 것이다. 현재 기록만으로 grip bias·마찰·drive 힘 중 하나를 확정 원인으로 정해 변경할 근거는 부족하다.

## 산출물 및 변경 범위

- `replay_instrumented.py`: 원본 경로에 읽기 전용 진단 기록을 추가하는 실행 스크립트.
- `analyze.py`, `metrics.json`: 원본/재생 비교와 수치 분석.
- `poses.jsonl`, `contact_points.jsonl`, `tip_geometry.npz`: 자세, 접촉점, 손끝 형상.
- `left_wrist.mp4`, `wrist_montage.png`, `overview_montage.png`, `grasp_timeline.png`: 시각 자료.
- `shared_stack_snapshot.json`: 원본 설정 사본.
- 재생 실행 로그: `outputs/shared_stack/grasp_8001_instrumented_20260906`.

프로덕션 소스와 설정은 수정하지 않았다. 변경은 outputs 아래의 진단 스크립트·로그·영상뿐이다. Real 프로세스/하드웨어, 정책 서버, 안전 한계는 변경하지 않았다. 검증은 동일 입력 전체 궤적 비교와 실제 실행에 한정했고, 제어 코드 수정이 없어 별도 단위 테스트는 추가하지 않았다. 최종 exit 4는 원본의 fault를 그대로 재현한 예상 결과다.
