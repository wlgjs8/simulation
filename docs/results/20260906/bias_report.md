# 보정 폼 장면에서 세 모델이 집지 못한 원인 — 2026-09-06

## 확인된 설정 오류와 수정

Sim 공통 설정에는 과거 gripper close bias **L=2 / R=6**이 남아 있었다.
사용자가 확인한 Real 성공 실행은 **0/0**이다. robotics_lab
`policy_runner/policy_runner/main.py:74`도 성공 로그
`outputs/sweep/20260904_235947_boltv2_plain_40k`의 적용 bias가 0이었음을 기록하며,
현재 기본값은 0/0이다. Sim은 같은 policy runner를 불러온 뒤 별도 설정의 2/6으로
덮어썼다 (`scripts/shared_stack.py:281`). 공통 코드를 사용한다는 사실만으로
실효 설정까지 Real과 같다고 검증하지 못한 누락이었다.

`flow_inference.py:2293`은 모델의 절대 opening percent에서 bias를 뺀다.
command gripper proprio는 보정된 명령을 다음 관측으로 되먹임하므로,
2/6은 최종 잡는 힘만 조절하는 값이 아니다. 닫힘 시점과 후속 정책 출력에도
영향을 준다. 8003도 grip proprio는 유지하므로 이 차이의 영향을 받을 수 있다.

`config/shared_stack.json`의 bias를 0/0으로 수정했다. 나머지 설정은 그대로이며
최종 기본 설정이 아래 실제 실행한 `bias0_settings.json`과 완전히 같음을 검증했다.

## 기존 세 영상의 직접 관찰

대상은 `outputs/shared_stack/foam_color_8001/8002/8003_20260906_0609`이다.
시각은 정책 시작 기준이며 MP4에는 앞에 공통 0.6초 tare가 있다.

| 모델 | 오른팔의 가장 낮은 TCP Z | 접촉/진행 |
|---|---:|---|
| 8001 | -219.54 mm | 손가락 접촉 기록 0. 접근 도중 공중에서 닫힘과 상승을 반복 |
| 8002 | -259.57 mm | 약 25.05초부터 검정 bolt_18 머리에 접촉하지만 완료로 이어지지 않음 |
| 8003 | -268.22 mm | 약 5.20초부터 여러 검정 볼트에 접촉하지만 완료로 이어지지 않음 |

폼 윗면은 -275mm이다. 세 모델의 왼팔 최저 TCP는 각각
-134.16/-146.31/-185.68mm로, 이 실행들에서는 왼팔이 파지 깊이에 도달하지 않았다.
30초 실행 중 안전 fault는 없었다. 이 표의 TCP Z는 손끝 전체 형상의 최저점과는 다르다.

8001 원본 입력을 `RecordedPolicySource`로 재생하며 손가락 형상과 볼트 자세,
손목 RGB를 추가 기록했다. 원본/재생 15,301 physics ticks, 양팔 30,602행의
관절 실제 위치·목표·속도 차이가 모두 **0**이었다. 형상으로 계산한 오른손 손끝은
전체 실행 동안 모든 볼트의 최고점보다 적어도 **34.39mm 위**에 있었다.
첫 닫힘 구간 1.94/2.61초에는 그 차이가 약 60.7/48.7mm였다.
볼트 원점의 최대 상승도 0.001mm 미만이었다. 기존 8001 실패는 정상 파지 뒤
마찰 때문에 떨어진 사건이 아니다. 실제 최대 선행 오차는 L=2.38/R=3.14mm였고,
FT 변위 보정은 L=0/R=0.011mm 수준이어서 안전/힘 제어가 파지 접근을 막은 설명도 맞지 않는다.

## bias만 0/0으로 바꾼 8001 실행

- 동일 checkpoint `boltv2_plain_40k/39999`, seed 100, 폼 색상/위치/물성,
  볼트 배치 파일, 카메라, C++ delta_preview/FT/IK/안전 설정을 사용했다.
- 실효 설정 차이는 `gripper_close_bias_left/right` 두 필드뿐이다.
  PhysX 안정화 후 초기 볼트 위치의 최대 차이는 **0.00554mm**, 각도는 **0.0338°**였다.
  접촉 모델 및 Real 설정 파일 hash는 같았다. 새 모델 추론의 diffusion sample과
  처리 지연은 고정하지 않았으므로 반복 실험 성공률이나 엄밀한 단일 원인 증명은 아니다.
- **30.002초, fault 없이 완료. 왼팔이 회색 bolt_04를 집어 회색 박스에 놓았다.**
- 왼팔 최저 TCP Z=-277.18mm, 오른팔=-276.50mm로 실제 파지 높이에 접근했다.
- 회색 bolt_04는 약 12.47초에 초기 높이보다 30mm 이상 들렸고,
  최대 **408.58mm** 상승했다. 약 15.79초에는 원점이 회색 박스 내부/벽 윗면 아래에 들어갔다.
  최종 전체 머리/몸통 형상도 박스 내벽 안쪽과 윗면 아래에 있음을 계산·영상으로 확인했다.
- 오른팔 검정 bolt_18은 최대 16.46mm 상승했지만 박스 이송을 완료하지 않았다.
  작업 지시 전체 성공이나 양팔 성공을 주장하지 않는다. 8002/8003의 bias 0 재평가는 아직 하지 않았다.

이 결과는 공유 bias 설정이 기존 실패의 중요한 원인이었음을 강하게 뒷받침한다.
또한 현재 PhysX/그리퍼/폼 조합이 적어도 회색 볼트 집기와 운반을 수행할 수 있음을 보여준다.
이전 세 영상은 모델 자체의 Real 집기 능력이나 모델 순위를 판단하는 근거로 삼으면 안 된다.

## 추가로 확인된 Real–Sim 차이

최근 수집 데이터 `pika/data/data_20260904_235111/episode_004.hdf5`에 카메라
내부 파라미터가 저장돼 있다. 가로 focal length는 왼쪽 393.32px / 오른쪽 393.78px이다.
현재 Sim은 `focalLength=11`, `horizontalAperture=20.955`, 폭 640px로 **335.96px**다.
동일 카메라 좌표의 물체가 가로 방향으로 약 **14.6–14.7% 작게 투영되는** 차이다.
실측 principal point와 왜곡 계수도 Sim의 중심 pinhole 가정과 다르다.
렌즈 pose는 CAD 기반 추정이며, 폼/박스 위치도 실제 셀을 완전히 계측한 상태가 아니다.
패드 색상 일치는 전체 카메라 관측 일치 검증이 아니다.

이 카메라 차이는 확인된 후속 보정 대상이지만, 이번 bias 실험에서는 카메라를 바꾸지 않았다.
남은 오른팔 실패의 단독 원인으로 확정하지 않는다. 다음 우선순위는 실제 장착 카메라의
intrinsics/그리퍼와의 상대 pose를 확인해 투영을 맞추고, 0/0 조건에서 세 모델을 다시 평가하는 것이다.
